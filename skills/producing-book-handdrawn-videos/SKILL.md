# 图书故事视频生产入口

下文的 `docs/`、`workspace/`、`src/` 路径均相对于 BV_Workstation 项目根目录，不是 Skill 安装目录。

## 先确定当前版本

先读项目 `AGENTS.md` 和 `docs/runbooks/longform-story-production.md`。已有作品先检查 Episode 的 `current_production.json`：存在时读取其指向的制作目录、`delivery.json` 与真实文件，核对路径和哈希，不用旧 Episode 阶段覆盖当前制作。不存在时按 Episode、profile、候选与批准清单恢复。`bv next` 会执行任务，不用于只读查询。

## 执行顺序

1. 确认输入和当前授权。新写稿先交完整正文及来源复查；用户提供现成稿并明确要求制作时，保留正文，落实本次授权，不重复索取相同许可。发现需要实质改稿时单独呈现修改，不能偷偷替换。不得把允许制作记录成已试听或已看图。
2. 新内容使用 story 路线：事件、冲突、应对、结果推进；以人物第一视角为主，必要时稳定第三视角。长度服从故事，6–8 分钟为参考，10 分钟为审阅提醒。不调用 human-writing 或去 AI 味检查器。用 `bv import-story --help` 获取实际导入参数；导入不等于批准。
3. 使用 [故事小节 AB](../bv-story-unit-ab/SKILL.md) 编写和校验小节计划。A 是起点，B 是正文发展后的高潮或结果。先完成结构与语义检查，再生成媒体；不能按时长切碎剧情。
4. 从 `src/bv/voice/data/doubao_voice_catalog.json` 选择适合故事的候选。来源核验、账户可用、试听结果、流行程度分别记录。沿用当前作品已选定的声音；需要试听时取当前正文的原文片段。正式 TTS 固定 `speed=1.12`，禁止再叠加后期加速。
5. 使用 [视觉合同](../bv-book-video-style-contract/SKILL.md) 处理画幅、字幕、标题、转场与编码。提前准备语义断句，保证重建正文一致。用正式音频和 ASR 绑定小节边界及 B 出场，不提前展示结果。
6. A 先生成，B 引用当前 A 路径和 SHA-256。按当前授权完成代表图及其余图；通常先展示开头、关键中段、结尾三对。用户已明确授权最终制作时继续完成，不新增重复批准要求。技术检查不替代审美或用户观看。
7. 检查全片解码、实际时长、字幕、人物连续性、AB 因果、转场与封面，交付最终视频、全幅代表图和清单。独立封面为 3:4。明确尚未完成的主观试听或观看，不把候选片标成用户验收通过。不自动上传。

## 边界

- 旧 value、固定三四组、黑白揭色仅用于历史兼容，不作为新长篇默认规则。
- 独立样片可做一个完整小节；受管正式流水线目前要求 3–48 对，不通过机械拆分凑足最低组数。
- 风格替换保留已批准故事和时间轴；正文、声音、结构改变时重新生成受影响依赖。
- 原稿、回执、媒体、当前作品状态放在忽略的工作区。共享代码与 Skill 不嵌入私人作品路径或凭据。
