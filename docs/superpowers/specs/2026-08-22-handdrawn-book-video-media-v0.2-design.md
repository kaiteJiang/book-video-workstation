# BV Workstation V0.2 手绘图书视频媒体流水线设计规格

- 日期：2026-08-22
- 工作区：`<repo-root>`
- 状态：书面规格已于 2026-08-22 获用户批准，实施计划已编写，尚未开始业务代码开发
- 产品形态：Codex 对话驱动的 Windows 本地工作流
- 首个技术验收：约 15 秒、1080×1920 的完整手绘样片
- 首个业务验收：一条 45 至 60 秒的整本书价值感悟视频

## 1. 规格关系与替代范围

本规格是 `2026-08-09-book-video-workstation-v0.1-design.md` 的媒体生产增量规格。

旧规格中以下内容继续有效：

- 书名/作者或 TXT、文字层 PDF、EPUB 输入。
- 全书研究、证据、价值提炼和生活连接。
- 第一条视频表达整本书带给读者的价值，不把一本书缩成单一观点。
- Codex 主执行、Grok 非阻塞审查、`human-writing` 自然化和文稿人工批准。
- IndexTTS2、火山 ASR、字幕、FFmpeg、真实书封、文件哈希、隐私和本地状态管理。

旧规格中以下内容由本规格替代：

- MiniMax H3/Grok 视频片段不再是默认视觉提供者。
- H3 导演提示词、15 秒片段拼接和人工视频片段导入不再进入 V0.2 默认链路。
- 第一版不开发新的用户 CMD、网页或 GUI；用户通过 Codex 对话推进流程。
- 人工关口由两个调整为三个：文稿批准、三张代表帧批准、最终成片批准。
- 视觉分镜从“视频镜头提示词”改为“配音时码驱动的手绘插画场景”。

旧 Grok/H3 适配器暂不删除，只保留为未启用的回退能力。历史状态和旧产物仍可读取，但不能混入新的手绘成片链路。

## 2. 目标与非目标

### 2.1 目标

在已批准文稿之后建立一条可追溯、可审核、可断点续跑的本地媒体流水线：

~~~text
批准文稿
→ IndexTTS2 黑金3完整配音
→ 火山 ASR 校准真实时码
→ 自动画风选择
→ 插画分镜和人物锁定
→ 开头/中段/结尾三张代表帧
→ 用户批准代表帧
→ 批量生成剩余插画
→ 1080×1920 手绘动画
→ FFmpeg 加入旁白、字幕和真实书封
→ 用户批准 final.mp4
~~~

V0.2 的成功标准是使用一本真实图书产出并验收一条 45 至 60 秒 `final.mp4`。仅有代码、模型初始化、静音画面、候选图片或测试夹具均不代表端到端完成。

### 2.2 非目标

V0.2 不做：

- 新的用户 CMD、网页工作台或 GUI。
- 抖音自动发布、账号管理或数据回传。
- 每个场景自动切换画风。
- 多个图片模型并行比稿。
- 自动生成或仿造图书封面。
- 背景音乐生成和复杂音效设计。
- 删除旧 H3/Grok 代码。
- 一次自动生成同一本书的第二、第三主题。

后续需要第二、第三条视频时，继续沿用现有主题去重机制，再生成新的整本书价值侧面；不在首次生产时预生成备用主题和插画。

## 5. 总体架构

### 5.1 模块边界

~~~text
Codex 对话
  ↓
BV MediaProductionService
  ├── voice          IndexTTS2 黑金3、规范化、WAV 检查
  ├── asr            火山 ASR、批准文稿对齐、敏感词检查
  ├── subtitles      SRT/ASS、断句和安全区
  ├── illustration   画风、人物、分镜、提示词、图片清单和审核
  ├── vendor renderer 9:16 Remotion 静音手绘动画
  ├── video          FFmpeg 音画、字幕和书封合成
  └── state          状态、哈希、失效传播和错误记录
~~~

建议新增的 Python 边界：

| 模块 | 单一职责 |
|---|---|
| `src/bv/illustration/contracts.py` | 定义画风决策、人物锁定、场景、图片任务和审核契约 |
| `src/bv/illustration/style_selector.py` | 规则初筛、候选排序和最终画风选择 |
| `src/bv/illustration/planner.py` | 根据批准文稿与真实时码生成插画分镜 |
| `src/bv/illustration/prompts.py` | 将场景、画风和人物锁定编译成图片提示词 |
| `src/bv/illustration/assets.py` | 导入、校验、哈希和恢复图片资产 |
| `src/bv/illustration/renderer.py` | 调用受控分叉并校验静音画面产物 |
| `src/bv/workflow/media_runtime.py` | 组装脚本批准后的媒体阶段，不承担具体媒体算法 |

最终文件名以实施计划和现有代码模式为准，但职责边界不得合并成一个大型脚本。

### 5.2 对话驱动含义

V0.2 不新增面向用户的 CLI 命令。Codex 在后台调用本地 Python、IndexTTS2、Remotion 和 FFmpeg；用户只在对话中：

1. 提供图书或书名/作者。
2. 批准文稿。
3. 发出“开始制作”，授权当前 Episode 生成配音、分镜和三张代表帧。
4. 批准或退回三张代表帧。
5. 批准或退回最终成片。

现有 CLI 不删除，内部服务不得依赖 Codex 聊天文本保存业务状态。Codex 中断或换任务后，系统必须依靠本地产物和状态文件恢复。


失败状态至少区分：

- `tts_failed`
- `tts_asr_mismatch`
- `style_selection_failed`
- `illustration_plan_failed`
- `representative_generation_failed`
- `representatives_rejected`
- `illustration_batch_failed`
- `visual_render_failed`
- `render_failed`

人工闸门：

1. `awaiting_script_review`：内容准确性与表达批准。
2. `awaiting_representative_review`：画风、人物、构图和布局批准。
3. `awaiting_final_review`：成片批准。

没有批准记录时，后续阶段必须失败关闭，不能根据文件存在推断批准。

## 8. 配音、ASR 与时间轴

### 8.1 配音

- 默认逻辑音色名为“黑金3”，具体参考音频和模型参数从本地配置解析，不在代码中写死私人文件路径。
- 完整文稿一次生成旁白，不按场景分别生成。
- IndexTTS2 的实际 `voice_master.wav` 是全片唯一时间轴。
- 产物必须经过 WAV 解析、采样率/声道/时长检查、响度规范化和 FFprobe 检查。
- 进程启动、CUDA 可见或模型初始化不等于配音成功；只有 WAV 与清单均合格才进入 `tts_ready`。

### 8.2 ASR 和字幕

- 火山 ASR 只接收最终旁白和必要热词，不接收完整电子书。
- ASR 结果与批准文稿进行字符/词级对齐。
- 数字、否定词、书名、作者和受保护词不一致时进入 `tts_asr_mismatch`。
- 字幕由批准文稿提供文字、ASR 提供时码，不直接采用 ASR 的识别文本替换文稿。
- 字幕最多两行；断句优先跟随语义和自然停顿，不能为了行宽改写文稿。

### 8.3 绝对帧契约

- `master_duration_ms` 来自最终 WAV。
- `total_frames = round(master_duration_ms × fps / 1000)`。
- 每个场景保存 `start_ms`、`end_ms`、`from_frame`、`to_frame`。
- 第一场从第 0 帧开始，最后一场结束于 `total_frames`。
- 场景之间无空洞、无重复归属帧。
- 转场发生在当前场景尾部的既有帧内，不从总时长扣除重叠。
- 最终画面轨与旁白总时长误差不得超过 1 帧。

## 9. 自动画风选择

### 9.1 输入维度

画风选择使用整篇批准文稿和 Episode 价值卡，提取：

- 叙事类型：感悟、关系、成长、知识解释、历史、寓言等。
- 情绪温度：温暖、克制、沉重、轻快。
- 抽象程度：现实生活或概念隐喻。
- 人物关系：独白、亲情、伴侣、群体、职场。
- 时间与文化背景。
- 目标读者与账号调性。

### 9.2 决策过程

1. 确定性规则对上游 20 种画风评分并选出三个候选。
2. Codex 根据完整文稿、候选画像和不适用条件选择一个主画风。
3. 输出选择原因、淘汰原因和置信度。
4. 人工可指定画风覆盖自动结果，但必须记录覆盖原因。

`style_decision.json` 至少包含：

~~~text
library_version
selected_style
candidate_styles
selection_reasons
rejected_reasons
confidence
manual_override
source_script_sha256
style_fingerprint
~~~

整条视频只允许一种主画风。场景可以调整明暗、色温和构图，但不能自动混搭两个画风配方。

## 10. 人物锁定与视觉叙事

默认采用“固定主人公＋少量隐喻插画”：

- 目标约 60% 场景出现同一个普通读者/生活主人公。
- 目标约 40% 场景使用书、门、道路、影子、人群等隐喻。
- 开头建立人物的现实困境。
- 中段呈现书如何改变理解框架。
- 结尾回到生活，用细微行动或神态表现变化。

60/40 是目标而非机械硬门槛。若书的内容不适合固定人物，分镜可以在 `illustration_storyboard.json` 中解释偏离原因；但必须继续满足“书籍与真实的人和生活发生联系”。

`character_lock.json` 至少记录：

- 角色身份和在叙事中的作用。
- 年龄区间、脸部特征、发型、体态。
- 基础服装和可允许的场景变化。
- 色彩标记和随身物件。
- 禁止变化项。
- 来源文稿哈希和画风指纹。

代表帧按顺序生成：先生成开头代表帧，用它建立主人公视觉身份；中段和结尾代表帧引用已生成的开头身份。三张图一起交付审核。批准后，剩余人物场景引用已批准的身份图和最相关代表帧，不能只依靠上一场图片连续传递，以免误差逐场累积。

## 11. 插画分镜契约

15 秒技术样片约 3 个场景；45 至 60 秒正式片约 8 至 12 个场景。单场通常 4 至 7 秒，以语义完整和手绘揭示可读性优先，不为凑数量硬切句子。

每个场景至少包含：

~~~text
scene_id
start_ms / end_ms
from_frame / to_frame
narration
narration_span
key_line
visual_purpose
setting
character_action
metaphor
composition
character_refs
style_lock
character_lock
image_prompt
negative_constraints
representative_frame
asset_status
~~~

约束：

- `narration_span` 必须覆盖批准文稿中的连续语义，不得改写文稿。
- 所有场景合起来必须覆盖完整旁白。
- `key_line` 为 6 至 14 个汉字左右的记忆点，不复制完整字幕。
- 画面不能增加文稿没有的事实、引语、疗效或人物经历。
- 不生成书中文字页、假封面、Logo、水印或难以校验的画内文字。
- 涉及时间跳跃、多人称、年龄敏感和历史环境时，必须明确视觉计划。

## 12. 图片生成与三张代表帧

### 12.1 提供者

V0.2 默认使用 Codex 对话中的图片生成能力。工作流先生成本地 `illustration_manifest.json` 和逐场提示词，Codex 再按清单生成图片并保存到 Episode 的图片目录。

不配置 `OPENAI_API_KEY`，也不自动回退到 API 模式。未来如增加本地图片模型，只能实现同一图片任务契约，不能改变上游分镜和审核规则。

### 12.2 图片层

- 每个场景只生成一张 1024×1024 彩色主图，使用无画内文字的安全构图；主图在 9:16 中央插画区按 `contain` 放置，不裁掉任何可见主体。
- 黑白线稿层由本地 FFmpeg/图像处理从批准彩色主图派生。
- 上游文字模式固定为 `font`；顶部主题句由 Remotion 使用本地字体渲染，避免图片模型生成错误中文。
- V0.2 不生成独立细节层；确认有必要后再增加。

每个图片任务记录提示词哈希、风格指纹、人物引用、输出路径、输出哈希、尺寸、状态和尝试次数。导入器在所有要求的主图存在且哈希匹配前不得激活分镜。

### 12.3 代表帧闸门

先生成：

- 开头：现实困境和人物身份。
- 中段：书籍带来的理解或转折。
- 结尾：人物回到生活后的细微变化。

审核检查：

- 主画风是否适合整篇文稿。
- 三张图中的主人公是否为同一个人。
- 年龄、服装、时代和场景是否合理。
- 画面是否准确对应旁白。
- 主体是否避开顶部主题句、底部字幕和抖音交互安全区。
- 是否出现错误文字、假书封、多余人物、Logo 或水印。

代表帧批准记录必须绑定三张图片哈希、分镜哈希、画风指纹和人物锁定哈希。任一绑定项变化后，旧批准立即失效。

15 秒技术样片只有约三个场景，因此三张代表帧就是该样片的全部插画；批准后直接进入静音画面渲染，不再创建一个空的“剩余插画批次”。

## 13. 1080×1920 画面设计

采用批准的 A 布局：

~~~text
┌──────────────────┐
│ 抖音顶部安全区      │
│ 6～14 字手写主题句  │
│                  │
│                  │
│   主要手绘插画区     │
│  文字→线稿→彩色揭示  │
│                  │
│   最终配音同步字幕   │
│ 抖音底部交互安全区    │
└──────────────────┘
~~~

固定技术输出：

- 1080×1920。
- 30 fps。
- H.264、`yuv420p` 静音画面轨。
- 白色或当前画风适配的浅色纸张背景填满整个 9:16 画布。
- 插画使用 `contain` 型安全构图，不允许用裁切掩盖比例问题。

布局要求：

- 初始安全区基线为：顶部平台预留 `y=0..139`，主题句 `y=140..339`，中央插画 `y=340..1459`，字幕 `y=1460..1659`，底部平台预留 `y=1660..1919`；关键主体不得进入右侧 `x=900..1079` 的交互预留区。
- 上述坐标必须集中保存在布局配置中；调整安全区只能改变配置和对应视觉基准，不能散改组件。
- 顶部主题句与底部字幕含义相关但职责不同，禁止逐字重复完整句子。
- 字幕最多两行，每行最多 18 个全角汉字等效宽度；进入抖音按钮/商品信息区域即判定失败。
- 右侧和底部安全区参数进入配置，不散落在组件常量中。
- 主题句、字幕和插画区域必须使用同一套可测试布局计算。
- 关键人物脸、书和主要动作不能被主题句、字幕或平台控件覆盖。

手绘揭示顺序：

1. 顶部主题句逐步出现。
2. 黑白线稿从左至右或按画风适配方向出现。
3. 彩色主图在同一构图上覆盖揭示。
4. 底部字幕独立跟随旁白时码，不参与图片揭示。

## 14. 最终合成

受控分叉输出 `picture_silent.mp4`。现有 FFmpeg 合成层继续负责：

- 将静音画面与 `voice_master.wav` 合并。
- 烧录最终 ASS 字幕。
- 在预留区域叠加用户提供的真实书封。
- 输出 H.264/AAC、1080×1920 的 `final.mp4`。
- 生成渲染清单、FFprobe 事实和 QC 报告。

V0.2 默认不加 BGM；如以后增加，只允许使用来源明确、音量受控的可选音床，不能影响旁白验收。

## 15. 失败处理、重试和失效传播

### 15.1 重试

仅技术性、幂等失败自动重试，最多两次，例如：

- 图片文件传输或保存中断。
- Remotion 子进程偶发退出。
- FFmpeg 临时文件生成失败且目标文件尚未发布。

以下问题不得自动无限重试：

- 画风不合适。
- 人物身份漂移。
- 构图错误或主题句区域被占用。
- 图片包含错误文字、假书封、Logo 或水印。
- ASR 发现数字、否定词、书名或受保护词不一致。

这些问题必须进入明确失败/退回状态，由 Codex说明原因和最小修正范围。

### 15.2 失效传播

| 变化源 | 必须失效的下游产物 |
|---|---|
| 批准文稿 | TTS、ASR、字幕、画风、分镜、图片、渲染、QC |
| 配音或音色 | ASR、字幕、分镜时间轴、渲染、QC |
| ASR 时间轴 | 字幕、分镜时间轴、渲染、QC |
| 画风或人物锁定 | 代表帧批准、全部图片、静音画面、最终渲染、QC |
| 单场提示词 | 该场图片、代表帧批准（若适用）、静音画面、最终渲染、QC |
| 书封 | 最终渲染、QC |
| 字幕样式 | 最终渲染、QC |

旧产物标记为 `stale`，不立即删除；新产物必须使用新的哈希身份发布。不得混合不同文稿、音频、分镜或画风身份的媒体文件。

## 16. 隐私、安全与日志

- 完整电子书继续只进入已批准的 Codex 内容分析路径。
- 图片生成只接收场景语义、画风、人物锁定和必要参考图，不接收完整电子书。
- 火山 ASR 只接收最终旁白和必要热词。
- 本地 IndexTTS2 参考音频、图片、书封和成片不进入 Git。
- API Key、Token、Cookie、登录会话和 Authorization 请求头不得写入源码、清单、日志或提示词。
- 子进程日志只记录安全错误码、退出码和脱敏命令结构，不回显凭证。
- 未经“开始制作”或代表帧批准，不得发起对应的图片生成批次。
- `final.mp4` 不自动发布抖音。

## 17. 测试策略

### 17.1 单元测试

- 画风规则评分、候选排序、覆盖和低置信度处理。
- 画风指纹与人物锁定哈希。
- 配音时码到绝对帧的换算和无缝覆盖。
- 主题句长度、字幕两行限制和布局安全区。
- 代表帧选择、批准绑定和批准失效。
- 图片清单完整性、哈希、尺寸和重复导入。
- 依赖失效传播。
- 错误码不包含私有路径或凭证。

### 17.2 集成测试

- 使用假图片提供者完成：批准文稿→假 WAV→假 ASR→分镜→代表帧闸门→批量图片→静音渲染→最终合成。
- 受控分叉的 TypeScript 检查、分镜校验和 Remotion 预览渲染。
- 15 秒 1080×1920 样片无黑边、无裁切、总帧数准确。
- 修改单个场景只使对应图片和下游渲染失效。
- 修改画风使三张代表帧批准和全部视觉产物失效。
- 旧 H3/Grok 状态仍可读取，但不能被新渲染器接收。

### 17.3 真实验收

真实验收不得用假提供者代替：

1. IndexTTS2 黑金3生成实际 WAV。
2. 火山 ASR 返回实际时码并通过文本对齐。
3. Codex 实际生成三张代表帧并经用户批准。
4. Codex 实际生成剩余插画。
5. Remotion 实际生成静音画面。
6. FFmpeg 实际生成 `final.mp4`。
7. 用户观看并批准成片。

## 18. 验收标准

### 18.1 15 秒技术样片

- 1080×1920、30 fps、H.264、无黑边。
- 使用真实 IndexTTS2 黑金3配音。
- 约 3 个场景，完成主题句、线稿和彩色插画揭示。
- 同一主人公身份稳定。
- 字幕来自最终配音，最多两行。
- 音画总时长误差不超过 1 帧。
- FFprobe、产物哈希、渲染清单和 QC 报告齐全。

15 秒样片只验证技术链路和画面语言，不替代 45 至 60 秒业务成片验收。

### 18.2 45 至 60 秒正式成片

- 表达整本书带给读者的价值和生活连接，不是孤立观点。
- 约 8 至 12 个语义完整场景。
- 三张代表帧批准后才生成整批插画。
- 全片只使用一种主画风。
- 人物与隐喻画面比例合理，偏离默认 60/40 时有解释。
- 没有假书封、错误画内文字、多余 Logo 或模型水印。
- 主题句、字幕和关键主体均处于安全区。
- 中断后能从最近合格阶段继续。
- 最终输出 `final.mp4` 和完整质量报告，但不自动上传抖音。

## 19. 实施阶段与工作量

| 阶段 | 内容 | 预计纯开发时间 | 验收 |
|---|---|---:|---|
| 1 | 引入并锁定上游代码、许可证和版本记录 | 0.5 天 | 原版示例可本地预览 |
