# 彩色剧情对墨染推进设计

**日期：** 2026-09-01
**状态：** 已获用户设计确认，待实施计划
**适用范围：** BV_Workstation 新建图书视频；已最终批准的旧 Episode 保持不变

## 1. 目标

把现有“单张黑白图停留后墨染成同一张彩色图”升级为“同一场景内两张连续彩色图推进剧情”。

每个场景由一个剧情对组成：

```text
彩色锚点图 A -> 按文稿语义转折点启动墨染 -> 彩色延续图 B
```

A 与 B 不是两个无关场景。B 必须延续 A 中的人物、地点、时间、镜头方向和画风，只推进一个与后半段台词直接相关的动作、互动或心理外显。以后更换画风时，只替换绘画语言和对应资产，不改变剧情对、语义切点、字幕、标题布局或转场结构。

## 2. 设计选择

采用“场景内双图剧情对”，不把 A、B 扁平化成八个独立场景，也不引入生成式视频或人物运动模型。

理由：

- 保留现有以旁白和 ASR 为全局时钟的架构；
- 不增加新的音频、字幕或发布边界；
- A、B 可通过强引用保持人物与构图连续；
- 墨染仍是稳定的表现层机制，画风仍可独立替换；
- 生成和审核成本明确，每个场景固定两张图。

## 3. 场景与时间合同

### 3.1 场景数量

- 新模式允许 3 或 4 个主要场景，默认 4 个；
- 每个场景必须有一组 A/B，因此总彩色图数量为 6 或 8 张；
- 当前常规书名作者流程继续默认 4 组、8 张；
- 场景仍使用 `S01`、`S02` 等稳定 ID，A/B 是场景内部阶段，不新增旁白场景。

### 3.2 语义转折点

每个场景在批准文稿中保存一个明确的语义转折：

- 转折前的封闭语义块对应 A；
- 转折后的封闭语义块对应 B；
- 转折位置保存批准文稿字符跨度，并通过最终音频的 ASR 对齐映射到毫秒和帧；
- 优先落在自然口语分句边界；
- 不允许用固定 50% 替代语义切点。

若语义切点无法可靠映射到最终音频，规划阶段必须失败并要求修复对齐，不能静默回退到机械时间比例。

为了保证两幅画都能被看清，场景边界规划需满足：

- A 在墨染前至少完整展示 30 帧；
- 墨染持续 45 帧；
- B 完成显露后至少完整展示 30 帧；
- B 必须在场景末尾 15 帧跨场景转场开始前完全显露。

若原场景不满足这些时长条件，应调整相邻场景的语义边界，而不是移动墨染点离开对应台词。

## 4. 分镜数据模型

新 Episode 的视觉模式记为 `color-story-pair`。旧 Episode 缺少该字段时继续按 `legacy-monochrome-reveal` 读取。

每个 `IllustrationScene` 增加以下语义：

```text
sequence_mode: color-story-pair
anchor_action: A 中已经发生的动作
continuation_action: B 中向后推进的单一动作
semantic_turn_span: 批准文稿中的字符跨度
semantic_turn_ms: ASR 映射后的时间
semantic_turn_frame: 渲染使用的绝对帧
anchor_prompt: A 图提示词
continuation_prompt: B 图提示词
continuity_constraints: A/B 必须保持的角色、服装、场所、镜头和道具
```

现有 `visual_purpose`、`setting`、`character_refs`、`composition` 和负面约束继续属于整个剧情对。`continuation_action` 不得引入本场景旁白之外的新事实、人物关系、时代或地点。

## 5. 图片任务与连续性

每个场景创建两个有序任务：

```text
S01-A  anchor
S01-B  continuation
```

资产使用明确文件名：

```text
S01_anchor.png
S01_continuation.png
```

新模式不再生成 `_bw.png`。

生成规则：

1. 先生成并导入 A；
2. B 的提示词必须包含 `continuation_action` 和 `continuity_constraints`；
3. B 必须把同场景 A 的准确路径和 SHA-256 作为强制图片参考；
4. B 仍可引用已批准的人物身份锚点，但同场景 A 是第一优先参考；
5. A 改变后，B、代表审批、静音画面、最终视频、QC 和交付候选全部失效；
6. B 改变时，A 保留，只使代表审批及其下游失效；
7. 已检查或已批准资产不得覆盖，替换前移入 Episode 的 `.private/history/<timestamp-purpose>`。

导入验证继续要求 1080x1920、PNG/JPEG、安全路径、当前调用明确产物和哈希一致。

## 6. 代表剧情对审批

代表审批从“代表单图”升级为“代表剧情对”。

- 按时间选择开头、最接近 50% 的中段和结尾三个场景；
- 每个代表场景必须同时生成 A 与 B；
- 一次展示三组 A/B，共 6 张；
- 审核画风、人物脸型、服装、道具、镜头方向、动作连续性和情绪是否与上下文一致；
- 任一代表场景缺少 A 或 B 都不能进入审批；
- 3 场景 Episode 的三组全部是代表组，批准后没有剩余图片；
- 4 场景 Episode 批准后只生成剩余一组，共 2 张。

用户批准代表剧情对，只授权生成当前 Episode 缺失的非代表 A/B 任务，不授权发布或修改文稿、音色和字幕。

## 7. 渲染合同

### 7.1 场景内渲染

- 场景本地帧 0 起完整显示彩色 A；
- 到 `semantic_turn_frame` 时开始显示 B；
- B 使用至少五个互相重叠的柔和径向墨水晕染区域逐渐覆盖 A；
- 晕染边缘需柔和、局部、无明显直线，不允许从左到右擦除；
- 墨染固定持续 45 帧，即 30 fps 下 1.5 秒；
- 墨染完成后完整显示 B，直至下一场景转场；
- 两张图都保持原始彩色，不应用灰度滤镜；
- 墨染过程中 A 始终作为底层，禁止纸白闪烁或空画布。

### 7.2 场景之间

- 当前场景完整 B 与下一场景完整 A 做 15 帧 cross-dissolve；
- 转场中点必须是真实混合，不允许白闪或硬切；
- 标题、作者、字幕层不参与图片墨染遮罩。

### 7.3 保持不变

- 1080x1920、30 fps、H.264、`yuv420p`；
- 旁白最终 WAV 是唯一全局时钟；
- 书名和作者在顶部中央全程显示；
- 字幕使用 Microsoft YaHei、白字深色描边、无黑底；
- 字幕断句继续由 `jl-oral-linebreaks` 生成并校验；
- 独立 3:4 作品封面、最终 QC、不可变交付候选和最终批准门保持不变。

## 8. 渲染输入兼容

渲染 storyboard 显式区分两种资产形状：

```json
{
  "sequence_mode": "color-story-pair",
  "assets": {
    "anchor": ".../S01_anchor.png",
    "continuation": ".../S01_continuation.png"
  },
  "semantic_turn_frame": 180
}
```

旧数据继续接受：

```json
{
  "assets": {
    "bw": ".../S01_bw.png",
    "color": ".../S01_master.png"
  }
}
```

旧的最终批准 Episode、历史交付包和批准哈希绝不迁移或重写。兼容只发生在读取和渲染路径，所有新建 Episode 默认写新模式。

## 9. 画风替换边界

稳定层包括：

- A/B 剧情含义和动作发展；
- 语义转折字符跨度、毫秒和帧；
- 人物、场所、道具、镜头方向和构图意图；
- 墨染 45 帧、五点以上局部晕染；
- 场景时长、字幕、标题作者和 15 帧跨场景转场；
- 最终媒体规格。

可替换层包括：

- style ID、媒介、笔触、纸张、纹理、调色和人物绘制语言；
- A/B 两张彩色图及其提示词和哈希。

画风替换必须同时重做每组 A 与 B；不得只替换其中一张。去除风格字段、提示词、资产路径和资产哈希后，新旧剧情对 storyboard 必须完全一致。

## 10. 失败与恢复

- A 未生成：B 任务保持阻塞；
- A 哈希与 B 记录的参考哈希不一致：拒绝导入 B；
- B 与 A 的角色、服装、地点或构图连续性未获代表审批：保留证据并重新生成该 B；
- 语义转折无法映射 ASR：停在分镜规划阶段；
- A/B 任一资产缺失或哈希变化：禁止渲染；
- 新模式 storyboard 使用旧 `bw/color` 资产键，或旧模式使用新 `anchor/continuation` 键：验证失败；
- 渲染失败不得改变最后一个稳定状态，也不得创建交付候选；
- 恢复时从第一个不完整门继续，不重新运行已经锁定的文稿、音色或 ASR。

## 11. 测试策略

实施必须按 TDD 进行，先写并观察失败测试，再写最小实现。

### 数据与规划

- 新 Episode 默认 `color-story-pair`，旧 Episode 缺省读取为 legacy；
- 场景数量只接受 3 或 4；
- 每场景必须有有效语义转折跨度、时间和帧；
- 语义转折无法对齐时失败，不回退 50%；
- A、墨染和 B 的最短展示时间得到验证。

### 图片资产

- 每场景任务顺序固定 A 后 B；
- B 未获得同场景 A 的哈希参考时不可生成或导入；
- 3 场景生成 6 张，4 场景生成 8 张；
- 代表审批必须绑定三组完整 A/B；
- A 变更会使 B 和下游失效，B 变更不删除 A。

### 渲染与像素验收

- 场景开头抽帧为完整彩色 A；
- 语义切点前一帧仍是 A；
- 墨染中点同时包含 A 与 B 的局部像素；
- 墨染结束后是完整 B；
- 遮罩至少五个径向晕染区域且没有直线推进边；
- B 在场景末尾跨场景转场前完全显露；
- 三个跨场景转场的起点、中点、终点均通过；
- 标题、作者和无黑底字幕保持稳定。

### 回归

- 旧 `bw/color` storyboard 仍可验证和渲染；
- 现有最终批准 Episode 和交付哈希不被修改；
- 文稿、音色、ASR、字幕、封面和交付测试继续通过。

## 12. Skill 更新

代码通过后更新以下现有 Skill，不新建重复 Skill：

1. `bv-book-video-style-contract`
   - 把稳定表现层改为彩色 A、语义墨染、彩色 B；
   - 把四张单图改为 3–4 组剧情对；
   - 更新画风替换和抽帧验收合同；
   - 保留 legacy 兼容说明。
2. `producing-book-handdrawn-videos`
   - 把代表图门改为代表剧情对门；
   - 明确 6/8 张彩色图、A 后 B 生成顺序和 B 的强引用；
   - 保持文稿、音色、字幕、封面、QC 和最终批准流程不变。

每个 Skill 修改先做无新指导的行为基线，再用同一场景验证修改后的指令，最后运行 `quick_validate.py`。

## 13. 完成标准

实现完成需同时满足：

- 新建测试 Episode 生成 3 或 4 组完整剧情对；
- A/B 提示词与资产哈希关系可追溯；
- 代表剧情对门无法被单图绕过；
- 实际 Remotion 抽帧证明彩色 A、局部墨染和完整彩色 B；
- 切换画风不会改变剧情对和语义切点；
- legacy 测试和现有主测试集通过；
- 两项 Skill 与代码行为一致并通过校验；
- 不修改任何已最终批准 Episode、批准记录或交付包。
