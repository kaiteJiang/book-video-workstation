## 1. 目标

BV Workstation 将一份完整、可正常打开且没有 DRM 限制的 TXT、文字层 PDF 或 EPUB 电子书，转换为一条可审核、可追溯、可断点续跑的抖音图书推荐视频。

V0.1 先验证一条最小闭环：

1. 完整电子书全部进入分析范围。
2. Codex 逐章建立证据，再完成全书综合理解。
3. 本次只生成一个 Episode E001，定位为整本书带给目标读者的核心价值与总体感悟。
4. E001 用一个具体人群和一条中心生活矛盾串联全书多个支撑观点簇，不把书缩成一个孤立观点。
5. Codex 生成文案并完成自然化与事实回查。
6. Grok 在选题和文案两个位置提供非阻塞挑刺。
7. 用户审核并批准文案。
8. IndexTTS2 使用固定授权声线生成完整旁白。
9. 火山 ASR 检查发音并提供字词时间戳。
10. 字幕和分镜跟随真实旁白时码。
11. 程序按照真实旁白时码生成 4 至 5 份 MiniMax H3 导演提示词；测试阶段先验收其中一个约 15 秒视觉片段。
12. 用户分段生成并导入 H3 视频；FFmpeg 本地拼接片段并叠加批准文案字幕、真实书封和完整旁白。
13. 自动技术质检后，由用户审核并批准 final.mp4。

V0.1 成功的定义是产出并验收一条真实 final.mp4。程序存在、模型初始化、CLI 帮助可用或单个步骤单独成功，都不等于端到端完成。

## 2. 已确认的产品边界

### 2.1 输入

- 单文件完整电子书。
- 支持 UTF-8、GBK、GB18030 等常见编码的 TXT。
- 支持正常 EPUB。
- 支持带文字层且阅读顺序可用的 PDF。
- 典型文件大小约 1 至 5 MB。
- V0.1 不支持扫描版 PDF OCR。
- 输入文件复制进项目，原文件不改动。

### 2.2 输出

- 一份可审核文案包。
- 一份经过 IndexTTS2 实际生成并校验的旁白。
- 与旁白同步的 SRT 和 ASS 字幕。
- 一份旁白驱动的完整分镜、连续性圣经和 4 至 5 份可直接复制给 H3 的分段提示词。
- 4 至 5 条经过逐段导入校验的 H3 视频素材；测试阶段允许先只导入 S01。
- 一条 45 至 60 秒、1080×1920、H.264/AAC 的 final.mp4。
- 一份最终审核报告和完整产物哈希记录。

### 2.3 人工关口

主人工关口只有两个：

1. 文案批准。
2. 最终成片批准。

H3 是明确的手动素材关口。用户复制每个分段提示词生成 H3 视频，再按 shot_id 用 CMD 导入。H3 暂不接 API，也不做浏览器自动化。

IndexTTS2 或 ASR 出现错误时进入修复状态，不增加常驻 GUI 审核页。最终审核中仍需试听音频。

### 2.4 模型分工

Codex 是主执行模型，负责：

- 章节分析。
- 证据卡。
- 全书综合。
- 生活连接。
- 整本书价值综合。
- E001 全书价值卡生成。
- 文案。
- 自然化。
- 事实差异检查。
- 主题去重。
- 分镜和 H3 提示词。

Grok 是非阻塞审查者，只负责：

- 主题的读者体感审查。
- 文案的读者体感审查。
- 后续 Episode 的重复感审查。

Claude 不进入 V0.1。

### 2.5 账号与内容定位

目标读者是 25 至 40 岁、正在处理关系、职场评价、自我选择和内耗问题的普通成年人。

账号承诺是：

> 每条视频讲清一本书能帮助什么样的人理解什么现实问题，以及它为什么值得读。

E001 不是章节摘要，也不是一本书中的单一知识点。它是一条整本书价值感悟视频：用一个目标读者和一条中心生活矛盾串联来自全书的多个支撑观点簇，回答这本书带给读者什么新的理解、判断方式或行动方向。

V0.1 不做流水账式整本书摘要、罗列式书单、作者生平介绍、抽象哲学讲座、孤立知识点讲解、虚构真实故事、无法验证的原话、心理治疗承诺和强硬带货。

内容单元固定为：

~~~text
一个具体的人和可识别的现实状态
→ 这本书如何重新解释状态背后的问题
→ 两至三个相互衔接的全书观点簇
→ 读者可能获得的理解变化和生活连接
→ 克制的整本书价值落点和阅读理由
~~~

## 3. 隐私和云端数据边界

用户已批准完整书籍内容用于 Codex 深度分析。完整覆盖通过逐章阅读、章节证据卡和全书综合实现，不要求一次请求把 1 至 5 MB 原文全部塞进模型上下文。

数据去向如下：

| 数据 | 去向 |
|---|---|
| 完整章节或安全分块后的原文 | Codex CLI |
| E001 全书价值卡或后续价值侧面卡、相关短证据和候选文案 | Grok CLI |
| 最终旁白音频和必要热词 | 火山 ASR |
| 场景、旁白语义和导演提示词 | MiniMax H3 |
| 电子书原文件 | 不直接交给 Grok、ASR 或 H3 |
| 密钥、Token、Cookie、Session | 不进入提示词、日志或 Git |

Codex 和 Grok 使用客户端订阅和现有登录会话。BV Workstation 不读取、复制或保存其登录 Token。

火山 ASR 凭证从 Windows 环境变量读取。普通配置只记录“从环境读取”，不记录真实凭证值。

H3 提示词可以包含最终文案语义和生活场景，不包含完整电子书。

发布抖音保持手动。发布时按当时平台规则完成 AI 生成或 AI 辅助内容声明。

## 4. 总体架构

系统采用阶段式 Python CLI 和文件状态机，不使用网页、数据库服务、任务队列或自治 Agent 框架。

~~~text
bv CMD
↓
阶段编排器
├── 状态与产物清单
├── 电子书解析
├── Codex 内容工程
├── Grok 非阻塞审查
├── IndexTTS2 旁白
├── 火山 ASR 与文本对齐
├── 字幕和分镜
├── H3 手动导入
└── FFmpeg 合成与质检
~~~

建议模块边界：

| 模块 | 单一职责 |
|---|---|
| cli | 解析命令并给出用户可执行的下一步 |
| state | 书籍、Episode、阶段状态、锁、事件和哈希 |
| ebook | TXT、EPUB、PDF 解析和来源锚点 |
| content | 证据、全书综合、主题、文案和去重 |
| models | Codex CLI 与 Grok CLI 的确定性调用适配 |
| voice | IndexTTS2 调用、音频规范化和时长检查 |
| asr | 火山 ASR、字符对齐和关键词检查 |
| subtitles | SRT、ASS 和安全区 |
| storyboard | 旁白驱动分镜和 H3 导演提示词 |
| video | H3 素材导入、FFmpeg 渲染和技术质检 |
| review | 文案审核包和成片审核包 |

模型之间不直接对话。Python 编排器决定调用顺序、输入、输出和重试边界。

## 6. 电子书解析

### 6.1 通用处理

1. 复制原始文件并保留只读来源。
2. 计算 SHA-256、大小、格式和导入时间。
3. 解析目录、章节和段落。
4. 建立来源锚点。
5. 执行质量检查。
6. 通过后生成 chapters/index.json 和章节 Markdown。

### 6.2 TXT

- 检测 UTF-8、GBK、GB18030 等常见编码。
- 统一换行，不润色原文。
- 识别常见章节标题。
- 无法识别章节时按安全长度切块。
- 保留行号和字符区间。

### 6.3 EPUB

- 使用 EPUB 目录和 spine 阅读顺序。
- 保留章节文件路径和段落位置。
- 区分正文、作者序、译者序、推荐序、出版信息和广告。

### 6.4 PDF

- 只接受有可用文字层的 PDF。
- 保留页面和文本映射。
- 检查多栏错序、页面重复和提取为空。
- 扫描 PDF 状态为 source_invalid，不在 V0.1 自动 OCR。

### 6.5 质量门槛

以下情况停止：

- 提取为空。
- 只有目录没有正文。
- 大量乱码替换符。
- 页面或章节灾难性重复。
- PDF 阅读顺序无法恢复。
- 章节数据不完整到无法保证全书覆盖。

少量出版信息、广告或结构不规则可以记录警告并排除，不修改原文件。

## 7. 全书证据链

### 7.1 逐章分析

Codex 按阅读顺序串行处理所有正文。每章输出严格结构化证据卡：

~~~yaml
claim_id: C07-004
claim_type: author_argument
paraphrase: 观点转述
evidence_excerpt: 短原文证据，仅供内部核对
source_anchor:
  chapter_id: chapter_007
  paragraph_start: 38
  paragraph_end: 41
reasoning:
  author_premise: 前提
  mechanism: 推理机制
  conclusion: 结论
limitations:
  - 适用边界
common_misreading:
  - 常见误解
life_signals:
  - 可连接的生活行为
confidence: high
~~~

原文引用必须回到规范化文本精确匹配。只有意思相近时标记为转述。角色观点、译者序和推荐序不能自动当成作者观点。

每章允许一次结构修复。修复后仍失败，状态为 chapter_analysis_failed，流程停止，不跳章假装完整。

章节缓存键包括：

~~~text
原书哈希
+ 章节哈希
+ 分析提示词版本
+ 输出结构版本
+ 模型标识
~~~

### 7.2 全书综合

全书综合从已验证章节卡构建，并可重新打开相关原文章节。输出：

- 全书主张图。
- 概念关系。
- 论证链。
- 书中案例。
- 限制条件。
- 常见误解。
- 读者适配。
- 未解决问题。

全书综合还必须生成 value_synthesis.json，用于回答“这本书给读者的价值是什么”，而不是只列概念：

- 全书核心价值主张。
- 最可能受益的目标读者。
- 读前常见认识或生活状态。
- 读后可能获得的理解、判断或行动变化。
- 一条适合贯穿视频的中心生活矛盾。
- 两至三个相互衔接的支撑观点簇。
- 每个观点簇对应的 claim_id、限制条件和章节分布。
- 为什么值得阅读原书，而不只是观看视频。

关键支撑观点原则上应来自至少三个不同章节或不同结构区域。书籍结构不足时允许减少覆盖区域，但必须在报告中明确说明，不能用一个章节或一个概念冒充全书价值。

全书报告中的关键判断必须引用 claim_id。找不到证据的内容不能写成“这本书认为”。

完整覆盖表示所有有效章节均进入分析和综合，不表示把整本书强塞进单次上下文。

## 8. E001 全书价值与后续按需去重

### 8.1 初次只生成 E001

第一次完成全书分析后，只生成一个 Episode。E001 固定为 whole_book_value：整本书带给目标读者的核心价值与总体感悟。系统不预先生成 E002、E003，也不建立 10 至 15 个视频主题池。

concept_map.json 是书籍结构分析，不计为视频主题。

### 8.2 E001 全书价值卡

E001 至少记录：

~~~yaml
episode_id: E001
episode_kind: whole_book_value
topic_name: 这本书如何帮助人重新拿回人生选择权
book_value_thesis: 这本书最值得目标读者带走的总体价值
target_reader: 长期按照他人期待安排生活的人
reader_before: 容易把别人的评价当成自己是否正确的证明
reader_after: 能区分自己需要承担的选择与无法控制的他人评价
central_life_tension: 想按自己的判断生活，又害怕不被认可
supporting_claim_clusters:
  - purpose_and_change
  - task_separation
  - freedom_and_courage
source_claim_ids:
  - C02-004
  - C07-006
  - C11-003
life_connection: 从反复解释和迎合，转向为自己的选择承担责任
practical_value: 提供重新理解自我、关系与选择的视角，不承诺消除痛苦
reading_reason: 视频只呈现价值主线，完整论证和边界需要回到原书
evidence_coverage:
  chapter_regions: 3
  claim_clusters: 3
constructed_scene: true
status: reserved
~~~

E001 必须同时满足：

- 只有一个中心价值主张，避免散成书摘清单。
- 至少两个、通常三个支撑观点簇形成递进关系，而不是并列报菜名。
- 支撑证据来自全书综合，不依赖一个章节或一个概念。
- 通过一个目标读者和一条中心生活矛盾把书与人的生活连接起来。
- 明确价值边界，不把“帮助理解”夸大成“保证改变”。

### 8.3 后续按需生成

只有用户运行：

~~~powershell
bv add <book-id>
~~~

系统才生成下一条 Episode。生成 E002 时读取 E001；生成 E003 时同时读取 E001 和 E002。后续 Episode 使用 episode_kind: value_angle，可以缩小到不同价值侧面，但仍必须回答“这本书在该现实处境下能帮助读者理解什么”，不能退化成孤立知识点视频。

每次只向用户交付一个通过检查的新主题。重复候选只保留脱敏失败原因，不进入正式主题库。

### 8.4 五层去重

1. 价值结构：全书价值主张、目标读者、中心生活矛盾、读前状态、读后变化和最终落点。
2. 观点与证据：支撑观点簇和首批核心证据重合度达到 50% 时标记高风险。
3. 生活表达：比较关系、可见动作和应用场景，防止只换场景不换结论。
4. Codex 语义：比较最终解释的问题、读者获得的价值和观众记住的结论。
5. Grok 体感：判断连续看到两条时是否像同一条内容换标题。

首批三个 Episode 只接受 distinct。related_but_close、too_close 和 duplicate 均不能通过。

E001 是覆盖全书支撑簇的母主题，任何合法的后续 value_angle 都必然与它共享较高比例的簇。因此，第二层的簇/claim Jaccard 阈值只在 value_angle 与既有 value_angle 之间比较，不用 E001 的全书证据覆盖直接否决后续角度。E001 仍参与第一、第三、第四和第五层去重；后续角度如果只是换标题、换场景或缩写 E001 的总体结论，仍必须拒绝。

Grok 保持非阻塞。如果 Grok 暂时不可用，确定性字段规则、证据重合检查和 Codex 语义去重仍必须全部通过；审核包记录 grok_review_skipped。Grok 失败不会让系统放宽前三层规则，也不会让重复主题通过。

如果三次约束修复后仍找不到独立主题，状态为 insufficient_distinct_topic。程序停止，不为满足数量放宽规则。

### 8.5 主题生命周期

- reserved：已生成并占用。
- script_approved：文案批准，主题正式锁定。
- produced：已有成片。
- published：已经发布。
- rejected：用户拒绝并保留原因。
- released：用户明确释放。

script_approved、produced 和 published 永久参与去重。删除视频文件不会抹掉主题使用历史。

Episode 表示独立主题和独立视频。Visual Variant 表示同一 Episode 更换视觉风格，不计入新主题。

## 9. 文案工程

### 9.1 生活连接

E001 从“一个人为什么需要这本书”开始，再落到可见动作。字段包括：

- 目标读者。
- 具体关系。
- 可见行为。
- 构造但合理的内心句。
- 情绪和现实代价。
- 全书价值主张。
- 两至三个递进的支撑观点簇。
- 每个观点簇的证据和边界。
- 应用边界。
- 可拍摄动作。
- 自然的阅读理由。

不得虚构朋友、读者、用户证言或作者原话。

### 9.2 语义锁

写文案前创建：

~~~yaml
must_include_claim: 必须表达的核心判断
must_include_value_thesis: 必须表达的整本书价值主张
supporting_claim_clusters:
  - 支撑观点簇一
  - 支撑观点簇二
  - 支撑观点簇三
must_not_claim:
  - 禁止扩大为普遍结论
source_claim_ids:
  - 证据编号
life_scene: 具体生活场景
book_name: 书名
audience: 目标读者
quote_allowed: false
constructed_scene: true
~~~

语言可以调整，事实范围不能漂移。自然化或缩写不得删除整本书价值主张、把多个观点簇压缩成孤立金句，或者用单一概念替代全书综合。

### 9.3 文案结构

45 至 60 秒初稿通常约 180 至 240 个汉字，只用于起草约束，最终以 IndexTTS2 的自然语速实际时长为准。

~~~text
0～6秒：目标读者能立即认出的现实状态
→ 6～15秒：指出这本书真正处理的深层问题
→ 15～35秒：两至三个支撑观点簇组成递进理解链
→ 35～50秒：把全书认识重新放回人的生活和选择
→ 50～60秒：价值边界、余韵和自然阅读理由
~~~

这不是按章节总结，也不是连续罗列概念。整条文案必须只有一条中心价值主线，每个支撑观点都推动读者从 reader_before 走向 reader_after。

每轮输出一版推荐文案和两个备选开头，不输出十个完整版本。

### 9.4 自然化

使用本地 human-writing Skill 的原则处理：

- 删除模型解释架子。
- 删除空泛总结和营销口气。
- 调整呼吸、停顿和口语节奏。
- 每句话只承担一个新信息。
- 不靠虚构经历增加人味。
- 不增加无来源细节。
- 不把“可能”改成“一定”。
- 不把作者立场改成公认事实。

自然化完成后重新执行事实差异检查。出现范围扩大、虚构引用、否定词丢失或语义锁冲突时，状态为 evidence_invalid。

### 9.5 Grok 审查

第一次审查 E001 全书价值卡或后续价值侧面卡，第二次审查文案。Grok 失败时记录 grok_review_skipped 并继续；审核包必须显示本轮缺少第二模型审查。

### 9.6 文案审核

review/script_review.md 包含：

- 目标读者和生活场景。
- 整本书价值主张、读前状态和读后变化。
- 推荐口播。
- 两个备选开头。
- 支撑观点簇、递进关系和价值边界。
- 证据编号和来源位置。
- 章节或结构区域覆盖情况。
- 构造场景声明。
- Grok 意见和 Codex 决策。
- 风险提示。
- 字符数和预估时长。

用户可以编辑推荐口播。批准时重新执行证据和语义锁检查，然后保存稳定脚本哈希。

## 10. 旁白、ASR、字幕和分镜

### 10.1 主时间轴

批准后的 IndexTTS2 完整旁白是唯一主时间轴。分镜、字幕和 H3 时段均从真实旁白时码产生。

### 10.2 固定声线

V0.1 一个账号只使用一个固定、本人拥有或明确授权的参考录音。记录 voice_id、参考文件哈希和人工批准状态。更换参考录音创建新版本，不覆盖旧版本。

IndexTTS2 必须显式指定实际模型目录：

~~~text
D:\Program Files (x86)\index-tts\checkpoints
~~~

不得依赖当前工作目录或错误的默认模型路径。不得静默改用 MiniMax 或其他云 TTS。

### 10.3 音频时长

- 理想旁白：48.0 至 56.0 秒。
- 可接受范围：45.0 至 60.0 秒。
- 低于 45.0 秒或高于 60.0 秒时不进入正式分镜。
- 最终视频跟随批准旁白和必要尾帧，必须处于 45.0 至 60.0 秒范围。

超时优先回到语义锁约束下缩写文案；过短则检查是否遗漏价值主张、支撑链或生活落点。V0.1 不依赖明显加速或减速凑时长。

### 10.4 火山 ASR

火山 ASR 的职责：

1. 检查 IndexTTS2 是否读对批准文案。
2. 提供字词时间戳。

最终字幕文字来自批准文案，ASR 只提供时间。程序用字符级序列对齐把 ASR 时间映射回批准文案。

通过标准：

- 书名、作者名、核心概念、数字和否定词必须通过。
- 普通文本规范化相似度目标不低于 94%。
- 低于 90% 硬失败。
- 90% 至 94% 进入修复或人工检查。

ASR 不可用时不静默按字符数平均分配正式字幕。可以修复配置，或由用户提供人工校验时间戳。

### 10.5 字幕

- 每个字幕单元约 6 至 14 个汉字。
- 每屏最多两行。
- 优先按标点和语义停顿分段。
- 每条至少约 0.6 秒。
- 书名和核心概念尽量不拆开。
- 右侧和底部预留抖音界面空间。
- V0.1 使用普通短语字幕，不做逐字动画。
- 输出 SRT 和 ASS，ASS 用于最终渲染。

字体必须存在且具有明确使用权。找不到字体时渲染前报错，不静默替换。

### 10.6 分镜

分镜输入是全书价值卡、批准文案、语义锁和 ASR 时码。完整旁白按真实字幕边界拆成 4 至 5 个 H3 片段，每段不超过 15 秒；每段内部建议 1 至 3 个克制的视觉节拍。

完整分镜通常承担：

1. S01：目标读者和现实状态。
2. S02：书对问题的第一层重新解释。
3. S03：第二、第三个认识形成转折。
4. S04：认识落回人的生活、关系或选择。
5. S05：价值边界、余韵和真实书封区域；旁白较短时可并入 S04。

画面使用具体动作，不要求 H3 表现抽象概念。

storyboard/continuity_bible.yaml 锁定主要人物的身份、年龄、脸部特征、发型、服装、道具、色调、摄影语言、时间连续性和禁止项。所有分段提示词都必须引用同一连续性圣经，避免多个 H3 片段像互不相干的视频。

## 11. H3 和最终合成

### 11.1 H3 边界

V0.1 按当前一次不超过 15 秒的方式手动使用 H3，但 15 秒只是视觉生成单元，不是 E001 正式成片时长。程序根据完整旁白生成 S01 至 S04，必要时生成 S05：

- 9:16。
- 全片原则上保持一个主要人物；每段必须遵守连续性圣经。
- 每段 1 至 3 个克制的视觉节拍。
- 人物不开口。
- 无旁白。
- 无字幕。
- 无书名文字。
- 无假书封。
- 无 Logo 和水印。
- 可保留自然环境声。
- 为字幕和真实书封预留区域。

程序生成 storyboard/storyboard.json、storyboard/continuity_bible.yaml 和 h3_prompt_S01.md 至 h3_prompt_S05.md。测试阶段先生成并验收 S01；通过后再生成其余片段。用户每生成一个片段后运行：

~~~powershell
bv import-video <book-id> E001 S01 "D:\Downloads\h3-S01.mp4"
~~~

原始视频复制保存，不移动、不覆盖。

S01 单片通过只代表 H3 视觉能力和提示词方向通过，不代表 E001 成片完成。只有全部必需 shot_id 均已导入、校验并参与最终合成，E001 才能进入最终成片审核。

### 11.2 H3 导入检查

- 文件可解码。
- 包含视频流。
- 宽高比接近 9:16。
- shot_id 存在于 storyboard.json，且不能重复导入覆盖既有原片。
- 单片时长大于 0 且不超过 15.5 秒；目标时长来自 storyboard.json。
- 相对目标时长的差值在允许范围内，不能通过明显加速破坏动作。
- 分辨率、帧率、编码和音频流有明确报告。
- 黑屏、静止或异常短帧产生警告。

人脸、手指、变装、乱码、意外说话和 AI 瑕疵由最终人工审核。

### 11.3 书封和声音

真实书封来源优先级：

1. 用户提供且与实际商品一致。
2. 从电子书提取并由用户确认。
3. 用户提供的官方商品图。

H3 不生成书封。书封文件记录哈希和用户确认状态。

V0.1 默认不加背景音乐。允许低音量、经过检查的 H3 环境声。不合格时只保留旁白。未来 BGM 只接受用户提供或明确有权使用的音频。

### 11.4 FFmpeg

最终输出建议：

~~~yaml
resolution: 1080x1920
aspect_ratio: 9:16
duration_seconds:
  minimum: 45.0
  maximum: 60.0
video_codec: H.264
pixel_format: yuv420p
frame_rate: 30
audio_codec: AAC
audio_channels: 2
faststart: true
~~~

FFmpeg 负责按 storyboard 顺序拼接 S01 至 S04/S05，并完成缩放、裁切、字幕、书封、完整旁白、可选环境声、最终响度和 MP4 输出。IndexTTS2 完整旁白始终是唯一主时间轴，不能把各 H3 片段的生成音频拼成旁白。

每个 H3 片段略长时可按 storyboard 目标时长裁切；短 0.3 秒以内可延长最后一帧；短得更多时停止并要求重新生成或人工批准特殊处理。片段调整后仍必须覆盖完整旁白时码，不能出现音频有内容而画面已结束的空档。

## 12. CMD 工作流

公开命令保持为九个：

~~~powershell
bv doctor
bv new "<book-file>"
bv next <book-id> [episode-id]
bv status [book-id] [episode-id]
bv open <book-id> <episode-id> script|h3|final
bv approve <book-id> <episode-id> script|final
bv import-video <book-id> <episode-id> <shot-id> "<mp4>"
bv retry <book-id> <episode-id>
bv add <book-id>
~~~

### 12.1 首次流程

~~~powershell
bv doctor
bv new "E:\电子书\被讨厌的勇气.epub"
bv next <book-id>
bv open <book-id> E001 script
bv approve <book-id> E001 script
bv next <book-id> E001
bv open <book-id> E001 h3
bv import-video <book-id> E001 S01 "D:\Downloads\h3-S01.mp4"
bv import-video <book-id> E001 S02 "D:\Downloads\h3-S02.mp4"
bv import-video <book-id> E001 S03 "D:\Downloads\h3-S03.mp4"
bv import-video <book-id> E001 S04 "D:\Downloads\h3-S04.mp4"
# storyboard.json 要求 S05 时，再导入 S05
bv next <book-id> E001
bv open <book-id> E001 final
bv approve <book-id> E001 final
~~~

bv next 每次只推进到下一个人工关口：

1. 初次推进到 awaiting_script_review。
2. 文案批准后生成完整旁白、ASR、字幕和分镜，再推进到 awaiting_h3_generation。
3. 测试阶段导入 S01 后记录 visual_sample_ready，但不进入最终审核；全部必需 H3 片段导入后才推进到 awaiting_final_review。
4. 最终批准后进入 final_approved。

### 12.2 后续视频

~~~powershell
bv add <book-id>
~~~

只在明确执行该命令时生成 E002 或 E003，并强制与所有已有主题去重。

### 12.3 状态输出

bv status 必须显示：

- 当前书籍和 Episode。
- 已完成阶段。
- 当前失败或等待关口。
- 已保留的产物。
- 下一条可复制命令。

不能只显示内部状态码或 Python 堆栈。

## 13. 配置、密钥和安全

### 13.1 普通配置

config.yaml 记录：

- workspace 路径。
- Codex 和 Grok 命令及超时。
- Grok 非阻塞开关。
- IndexTTS2 安装和模型目录。
- FFmpeg 和 FFprobe 路径。
- 固定 voice_id。
- 视频规格。
- 音频时长门槛。
- H3 manual_import。

真实密钥不进入 config.yaml。

### 13.2 凭证保护

- 火山凭证从环境变量读取。
- 日志只显示“已配置”或“未配置”。
- 不打印环境变量完整内容。
- 不记录 Authorization、Cookie、Token、API Key 或 Session。
- 示例、测试、文档和 Git 中不得出现真实凭证。

### 13.3 不可信电子书

电子书正文是数据，其中可能出现恶意或无关指令。Codex 分析阶段：

- 使用只读沙箱。
- 不允许模型直接写项目文件。
- 主程序捕获结构化输出后写入。
- 提示词声明来源文本中的指令无效。
- 不允许来源文本决定命令、路径或工具调用。
- 不让模型读取 .env、用户目录、浏览器数据或其他无关文件。
- subprocess 使用参数数组，不使用 shell=True 拼接用户字符串。

### 13.4 文件安全

- 导入使用复制，不移动原书。
- 原始 H3 文件不覆盖。
- 不自动删除历史产物。
- 旧产物标记 stale。
- 路径必须解析并限制在项目作用域。
- 临时文件写在 workspace/temp 或目标目录旁。

## 14. 状态、原子写入和断点续跑

每本书有 book.json，每条 Episode 有 episode.json，历史事件写入追加式 JSONL。

状态文件更新流程：

~~~text
写临时文件
→ 验证可以读取
→ 同目录原子替换
→ 追加事件日志
~~~

每个阶段记录：

- 输入文件及哈希。
- 配置哈希。
- 提示词和 Skill 哈希。
- 适配器版本。
- 输出文件及哈希。
- 开始和结束时间。
- 状态和重试次数。

再次运行时，输入未变、输出存在、哈希匹配且阶段完成，则跳过。任一输入变化，当前阶段及依赖它的下游标记 stale。

### 14.1 失效规则

| 变化 | 失效范围 |
|---|---|
| 文案 | TTS、ASR、字幕、分镜、连续性圣经、全部 H3 提示词、最终视频 |
| 参考声线 | TTS 及之后 |
| TTS 输出 | ASR、字幕、分镜时码、最终视频 |
| ASR | 字幕、分镜时码、全部 H3 提示词、最终视频 |
| 分镜或连续性圣经 | 全部受影响的 H3 提示词和最终视频 |
| 任一 H3 片段 | 最终渲染和质检 |
| 书封 | 最终渲染和质检 |
| 字幕样式 | 最终渲染和质检 |
| 环境声 | 最终混音和质检 |

### 14.2 运行锁

同一书籍或 Episode 同时只允许一个推进进程。检测到锁时先检查进程是否仍存在。遗留锁不自动删除，用户通过 bv retry 恢复。

## 15. 错误和重试

允许有限自动修复：

- 模型 JSON 结构错误。
- 缺少必填字段。
- 锚点格式错误。
- Grok 输出格式错误。
- 临时网络错误。
- IndexTTS2 偶发进程错误。
- FFmpeg 临时文件占用。

必须停止：

- 电子书乱码或扫描 PDF。
- 原文证据不存在。
- 文案缩写会改变核心观点。
- IndexTTS2 核心名词持续读错。
- 火山凭证无效。
- H3 比例错误且裁切损坏主体。
- 书封版本不确定。
- 最终画面有明显异常。
- 找不到独立的新主题。

错误输出包含：

- 失败阶段。
- 错误代码。
- 用户可理解的原因。
- 已保留结果。
- 未执行阶段。
- 下一条建议命令。
- 脱敏日志路径。

不向普通用户只显示堆栈。

## 16. 版本和可复现性

模型产物记录：

- Prompt 名称、版本和 SHA-256。
- 输出 Schema 版本。
- human-writing Skill 哈希。
- 模型提供方和可获得的模型标识。
- Codex/Grok CLI 可获得的版本信息。

提示词或 Skill 升级不自动重做已经批准的视频。新 Episode 使用新版本。重新生成旧 Episode 时提示版本变化。

## 19. 开发顺序

### 阶段 0：真实工具冒烟测试

- Codex 最小结构化请求。
- Grok 最小结构化请求。
- IndexTTS2 实际短 WAV。
- FFmpeg 测试 ASS。
- 火山 ASR 测试 WAV 和时间戳。
- H3 样例导入和 FFprobe。

### 阶段 1：CLI、配置和状态机

- bv doctor、new、status、next。
- 原子状态、事件日志、运行锁和脱敏。

### 阶段 2：电子书解析

- TXT、EPUB、文字层 PDF。
- 质量门槛和来源锚点。

### 阶段 3：全书证据链

- Codex 逐章分析。
- Schema 校验。
- 引用回查。
- 章节缓存。
- 全书综合。

### 阶段 4：E001、文案和主题账本

- E001 全书价值卡。
- 目标读者、读前状态、读后变化和中心生活矛盾。
- 两至三个递进的全书支撑观点簇。
- Grok 两次审查。
- human-writing 自然化。
- 事实差异检查。
- 文案审核和批准。
- bv add 按需去重。

### 阶段 5：旁白、ASR、字幕和分镜

- IndexTTS2。
- 固定声线。
- ASR 对齐。
- SRT、ASS。
- 旁白驱动分镜。
- 4 至 5 份 H3 分段提示词和连续性圣经。

### 阶段 6：H3 导入、FFmpeg 和最终质检

- 按 shot_id 导入并校验 H3 片段。
- 先验收一个约 15 秒视觉样片，再补齐正式成片所需片段。
- FFprobe。
- 真实书封。
- final.mp4。
- 最终审核和批准。

### 阶段 7：真实端到端验收

使用《被讨厌的勇气》先完成一个约 15 秒 S01 视觉样片验收，再完成一条 45 至 60 秒真实 E001。

## 20. 测试策略

### 20.1 单元测试

- 编码和章节识别。
- 来源锚点。
- 编造引用拒绝。
- Schema 修复。
- 主题结构去重。
- 全书价值卡不能退化成单观点或章节摘要。
- 支撑观点簇覆盖不同章节或结构区域。
- ASR 错词和否定词。
- 字幕分段。
- 哈希和失效传播。
- 原子状态恢复。
- 日志脱敏。

### 20.2 格式测试

- UTF-8 TXT。
- GB18030 TXT。
- 正常 EPUB。
- 文字层 PDF。
- 扫描 PDF 拒绝样例。

测试样本使用自建或可公开使用的短文本，不把用户完整电子书提交进 Git。

### 20.3 集成测试

- 模拟 Codex/Grok 输出。
- 模拟 IndexTTS2 成功与失败。
- 模拟 ASR 时间戳和错词。
- 使用多个短测试视频验证 FFmpeg 拼接、时码覆盖和最终封装。
- 中断章节分析后续跑。
- 修改脚本后验证下游 stale。

### 20.4 私有端到端验收

《被讨厌的勇气》只放 workspace/books，不进入 Git。验收完整链：

~~~text
完整电子书
→ E001 文案审核
→ 真实 IndexTTS2 旁白
→ 火山 ASR
→ 字幕和分镜
→ 手动 H3 分段生成与导入
→ FFmpeg
→ final.mp4
~~~

## 21. 自动和人工质检

### 21.1 自动技术质检

- MP4 可解码。
- 视频流和音频流存在。
- 45 至 60 秒。
- 1080×1920。
- H.264、AAC、yuv420p。
- 音频无明显削波和异常长静音。
- 字幕无重叠和越界。
- 批准文案全部覆盖。
- 书封、旁白、字幕和全部必需 H3 片段哈希有效。
- 没有 stale 输入。

### 21.2 人工成片质检

- 人物一致。
- 肢体和手指正常。
- 无乱码、假文字、Logo 和水印。
- 无明显无对白开口。
- 动作符合旁白。
- 字幕可读且不被界面遮挡。
- 书封与商品版本一致。
- 书名和概念读音正确。
- 没有强营销、虚构证言或治疗承诺。
- 发布时完成当时平台要求的 AI 内容声明。

## 22. V0.1 不做

- 网页或 GUI。
- 数据库服务。
- 后台目录监听。
- H3 API。
- 浏览器自动化。
- 自动上传抖音。
- 自动挂商品链接。
- 多账号矩阵。
- 超过 60 秒的长视频。
- 自动背景音乐。
- 数字人和口型同步。
- 多声线自动选择。
- 扫描 PDF OCR。
- 向量数据库。
- 多书并发分析。
- 无限重试。
- 初次自动生成三主题。
- 无审核发布。

## 23. 完成标准

V0.1 必须同时满足：

1. CMD 能导入 TXT、EPUB 和文字层 PDF。
2. 完整书籍经过逐章分析和全书综合。
3. E001 的全书价值主张和支撑观点簇可追溯到原书不同章节或结构区域。
4. 初次只生成 whole_book_value 类型的 E001。
5. E001 说明整本书带给目标读者的价值，并通过一条中心生活矛盾连接具体的人和可见动作，不退化成孤立观点。
6. 文案经过自然化和事实回查。
7. 用户可以修改和批准文案。
8. IndexTTS2 实际生成可用旁白。
9. 火山 ASR 完成发音检查和时码。
10. 字幕使用批准文案并与旁白同步。
11. 分镜按真实旁白时码拆成 4 至 5 个不超过 15 秒的视觉片段。
12. 连续性圣经和每段 H3 提示词可以直接复制。
13. 测试阶段可以先验收一个约 15 秒片段，正式阶段可以按 shot_id 导入全部必需 H3 片段。
14. FFmpeg 生成正确的 45 至 60 秒竖屏 MP4。
15. 真实书封正确。
16. 自动质检通过。
17. 用户批准成片。
18. 失败可以断点续跑。
19. 上游变化触发正确失效范围。
20. 密钥和 Token 不进入日志、配置或 Git。
21. 电子书、录音和成片不进入 Git。
22. 只有用户执行 bv add 时才生成后续独立主题。
23. 没有自动发布或未授权外部操作。

## 24. 最终设计结论

V0.1 的闭环为：

~~~text
完整电子书
→ 可信解析
→ 全书证据链
→ E001 整本书价值综合
→ 一条生活主线串联多个支撑观点簇
→ 45 至 60 秒自然化且可回查的文案
→ 人工批准
→ IndexTTS2 完整旁白
→ 火山 ASR 校验与时码
→ 精确字幕和分镜
→ 先验收一个约 15 秒 H3 视觉样片
→ H3 手动分段生成并导入全部必需片段
→ FFmpeg 拼接和本地合成
→ 自动质检
→ 人工成片批准
→ 未来按需生成下一条且强制去重
~~~

该设计能够在不引入 GUI、数据库、工作流引擎和复杂 Agent 系统的条件下安全落地。V0.1 先用一个约 15 秒 H3 视觉样片验证生成方向，再完成一条 45 至 60 秒的整本书价值感悟成片；后续功能只根据真实成片和账号数据增加。
