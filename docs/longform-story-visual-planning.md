# 长篇故事视觉规划

语义规则以 `skills/bv-story-unit-ab/SKILL.md` 为准；执行顺序见 [生产手册](runbooks/longform-story-production.md)。

媒体规划前必须存在与批准正文一致的 `script/ab_units.json`。每节连续覆盖原文，记录 A 的处境、中间事件、B 的高潮或结果、状态变化、事实依据与唯一的 B 出场原文。结构校验不代表事实或艺术判断已通过。

`IllustrationPlanningStage` 先读取完整批准合同，再把小节字符边界映射到正式 ASR 的字幕起点。story 路径使用严格边界：目前要求 3–48 对；若映射丢失边界、出现不足 4 秒窗口或 B 揭晓位置漂移，则报错要求重新规划。不会自动合并小节，也不会切开最长窗口凑够三对。旧 value 路径的窗口回退不适用于 story。

技术样片必须覆盖完整小节，先验证完整批准稿，再平移局部字符跨度。独立单小节样片不等于受管正式流水线已支持一对场景。

人物来自批准元数据的 `characters`，最多 24 个 `source-` ID。保持身份和因果，允许正文支持的时间、地点、年龄、服饰与机位变化。B 绑定本组当前 A 的路径与 SHA-256，跨组保留人物锚点。

代表组选择开头、关键中段和结尾，不能写死为 S01/S03/S04。全部场景连续覆盖正式音频，最后一帧由音频时长决定。墨迹转场保持 45 帧，组间溶解 15 帧。小节数没有按分钟配额；6–8 分钟与 10 分钟提醒不能触发自动变速。
