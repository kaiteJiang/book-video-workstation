# 图书长篇故事生产

## 入口与恢复

总入口为 `skills/producing-book-handdrawn-videos/SKILL.md`；故事语义与视觉规格分别由两个专项 Skill 维护。本文路径相对于项目根目录。

已有作品先只读检查 `current_production.json`。若存在，核对其指向目录属于当前 Episode，并读取该目录的 `delivery.json`、文件哈希和待审事项；不要从旧 `episode.json` 的媒体停点重跑独立制作。清单缺失、路径越界或哈希不一致时先查明原因。没有指针时再按 Episode、profile、当前候选及批准合同恢复。`bv next` 不是状态查询。独立制作的清单恢复目前由 Agent 执行，不能宣称 CLI 已自动接管。

用户提供现成稿并明确要求直接制作时，保留原文并落实该稿的制作授权；有实质事实修订则先交修订内容。授权已覆盖的阶段不重复询问，但不得伪造试听、看图或最终观看记录。新写出的稿件仍需当前候选批准。不要把一次作品授权推广到其他作品。

## 从故事决定长度

新创作推荐 story 模式：人物第一视角优先，必要时第三视角；从书中选择一条值得讲透的核心故事。冲突、选择、结果和回扣应当连成一条线。6–8 分钟是预算参考，10 分钟是审阅提醒，不是凑字数或自动压缩音频的指令。

候选稿包含正文、选段理由、来源材料、角色认知范围、连续的叙事段落跨度、逐段事实复查。原著引语、转述和解释须区分。没有整书正文时明确资料覆盖范围，缺失细节补核后再写，不用目录或书评冒充通读。

story 路径不使用 human-writing 或去 AI 味检查。旧 value 路径保留用于历史项目，不应套到本模式。

## 登记与审批

`bv import-story` 接收正文和 JSON 复查记录；参数以 `bv import-story --help` 为准。导入只登记 `awaiting_script_review`。使用不同候选名保留旧稿，修改正文后重新复查与导入，旧批准不会自动套到新内容。

用户完整审阅当前候选后，才运行 `bv approve <book_id> <episode_id> script`。本命令必须校验候选、证据、段落与复查的哈希。随后进入声音试听门禁；任何新候选均不得生成 `approved.txt` 冒充已批稿。

新作品仍可用 `bv new --title ... --author ...` 建立身份，再按 story 路线准备文稿并导入。不要用旧的 value 自动起稿流程代替直接故事创作。导入时将本 Episode 迁移到长篇 profile，并保留旧 profile 供追溯；其他作品不迁移。

正文按 UTF-8、LF 换行落盘后计算字符跨度及哈希。批准后不再转换换行或静默改字；已有原始文件保留。AB 结构校验使用读取后的正文文本哈希，交付文件校验使用实际字节哈希，二者不要混用。书籍作者未知时显式填写 `authors: []`，且必须与书籍身份一致，不能用篇名、讲述者或占位人名补齐。

## 声音池

见 [声音池说明](../voice/doubao-story-voice-pool.md)。目录是官方名称和 ID 已核验的候选池，实际试听状态为 pending。以人物性别/年龄感、故事类型和情绪变化筛选最多三种声音。

先展示候选与理由，再在稿件批准后的试听阶段使用同一段代表正文。选段可以来自正文中间，需具有叙述与情绪变化，保留原文字符跨度和 SHA-256。不得为了试听而另写一段更好听、却不属于已批准正文的文案。

实际调用前核验账户能使用这些音色。确定声音后以固定 `speed=1.12` 生成正式音频，禁止叠加后期加速，测量真实时长；比十分钟稍长先提示审阅，不自动加速或裁切。实际合成、ASR、声音主观表现及供应商兼容性必须有真实记录才可标为通过。

story 模式的极速 ASR 使用长音频请求边界（2 小时、100 MB，300 秒请求超时）；旧模式保留原有限制。校验与识别仍绑定正式 WAV 的真实字节和 SHA-256，不为绕过旧时长限制而重采样或重合成。逐位读出的年份（如“一六〇一”与“1601”）按同一数字比较，不同年份仍必须报错。

在定稿审阅前预检字幕断句，尽早发现需要改写的长句。批准后，依照同一份 `approved.txt` 准备 `script/subtitle_breaks.txt`：按自然口语语义逐行断句，保持正文内容不变。这是现有 AB 路线必需的字幕输入；改稿后须重新准备，不能沿用旧短稿断句。字幕阶段再把这些语义块对齐到实际 ASR，不使用去 AI 味检查器。

## 动态 AB

先选择一个值得讲完整的故事，再按处境、冲突、选择和后果划分叙事小节；不按字数、单句话或手势平均切图。每对 A 表达小节的起点，B 表达经历发展后的高潮、结果或新困境。逐对写清“A 时是什么处境—中间发生什么—B 时改变了什么—这如何引出下一节”。配音完成后，将 B 的出场对齐到正文讲到该结果的真实 ASR 边界，不能提前揭晓。

每段时间都应被画面覆盖。小节长度由完整发展决定，不为凑对数拆成微动作，也不为凑时长拉长静帧。十分钟十几对是整体框架的量级示例，不是固定配额；有的小节可讲一两分钟，有的转折较短。区分视频讲述时长与故事经过的时间，两者不能互相冒充。大量解释而缺乏事件发展的正文，应先改稿，不能靠图片虚构经历补足。

每对 B 引用当前 A 的图片路径和 SHA-256，用于人物身份、画风及故事关系的参考，不用于强制复制 A 的镜头。时间、地点、年龄、服饰、在场人物和构图可以随有依据的剧情发展改变；分别记录 A、B 的时点、地点、人物状态与变化依据。不能只改手势、表情、卷宗位置就宣称完成一个叙事小节，也不能把无因果关系的两个名场面硬配成一对。墨迹转折对齐语义变化，保持 45 帧；组间交叉溶解保持 15 帧。

代表图仍先用开头、关键中段、结尾三对；动态场景不能假定代表图总是 S01/S03/S04。代表图批准后再补其余组，缺图或替换导致的依赖失效必须显式处理。

## 验收

自动检查：正文与批准哈希一致；音色/语速/配音记录绑定；ASR 与段落跨度正确；全部场景覆盖时间轴；AB 成对且 B 引用当前 A；代表组与全部资产状态正确；图像、字幕、转场、实际视频时长及输出规格。

人工检查：故事是否值得听完、人物认知是否越界、声音是否耐听、关键反转是否被提前泄漏、同人物是否连续、精彩处是否得到足够画面、结尾是否完成开头提出的冲突。

完整视频与 3:4 独立封面仍需最终审阅。配置、分镜表、脚本或测试通过都不能替代真实成片与最终检查。

交付状态 `complete_for_user_viewing` 仅表示候选可供观看，必须与用户最终验收区分。全片解码、ASR 一致性和关键帧检查不等于完整主观试听或观看；交付报告按实际证据分别记录。
