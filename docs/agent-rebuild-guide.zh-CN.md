# 把这个仓库丢给 Agent，复刻一条图书视频

你可能遇到过这种情况。

你让 AI 推荐一本书，它很快写出一段文案。再让它做成视频，它也会很快告诉你已经完成。等你打开文件，声音不对，字幕没跟上，画面风格来回变，封面还是临时凑的。最麻烦的是，你不知道问题出在哪一步，也不知道哪份文件才是最终版。

BV Workstation 想解决的就是这件事。

它把一本书到一条短视频拆成几个能检查的阶段。文稿先给人看，音色用同一段话试听，背景图先看三张代表图，最后再检查真实成片。每次批准都绑定当前文件的 SHA-256。内容变了，旧批准自然失效。

这篇文章面向第一次把仓库交给 Agent 的人。你不需要先学会 Python，也不用一口气弄懂所有配置。照着做，Agent 就能先帮你检查环境，再从第一个未完成的门禁继续。

## 先认识这套工作台

项目有五个很具体的特点。

第一，输入可以是书名加作者，也可以是你有权使用的 TXT、PDF、EPUB 文件。只有书名和作者时，Agent 要先确认书籍身份和证据边界。它如果装了微信读书工具，可以读取你账号有权访问的元数据、目录、划线和书评。没有这个工具，就该请你提供合法材料，不能凭印象补全整本书。

第二，新建短视频的口播时长被锁在 30 到 45 秒，目标落在 35 到 40 秒。旧项目没有生产配置时，仍保留 45 到 60 秒的兼容规则。Agent 不能把两套规格混在一起。

第三，一条新视频总计使用四张背景图。画风固定为目录里的第 11 种 `retro-gouache-concept`，也就是中古动画水粉概念稿。开始只生成开头、中段、结尾三张代表图。你确认人物和氛围以后，它才补第四张。

第四，竖屏成片是 1080×1920、30fps，转场为 15 帧交叉溶解。独立作品封面是 1080×1440，也就是三比四。视频封面和视频里的真实书封是两种不同资产，不能拿一张图到处顶替。

第五，云端 TTS、ASR 和图像生成都被放在显式授权之后。仓库里的配置只记录环境变量名称。电子书、声音样本、供应商回执和成片默认放在 Git 忽略目录中。

## 你要准备什么

准备一台 Windows 10 或 Windows 11 电脑，安装 Python 3.11、uv、FFmpeg、FFprobe、Node.js 和 npm。你还需要一个能读取项目文件、运行终端命令的 Agent，例如 Codex。

音频路线可以按你的条件选择。本地 IndexTTS2 适合不想把文稿交给云端的人。豆包长文本 TTS 和火山 ASR 需要自己的账号、权限和余额。项目不会附带任何密钥或额度。

书籍材料也要提前想清楚。只用自己有权访问的电子书、笔记和公开资料。不要把受版权保护的整本书上传到公开仓库。

## 第一次安装

打开 PowerShell，依次运行下面的命令。

```powershell
git clone https://github.com/kaiteJiang/book-video-workstation.git
Set-Location book-video-workstation
uv sync --group dev
Copy-Item config.example.yaml config.yaml
uv run bv doctor
```

`doctor` 会检查本机依赖和配置。看到失败先别急着改代码。让 Agent 逐项说明缺少什么、它准备改哪个配置、改完如何复查。

接着打开 `config.yaml`。把 FFmpeg、FFprobe、字幕字体、本地模型等路径改成你电脑上的实际位置。真实密钥只放进本机环境变量，不要写进 YAML、聊天记录、测试文件或截图。

项目默认认识这些环境变量名称。

```text
BV_DOUBAO_TTS_API_KEY
BV_VOLC_ASR_API_KEY
BV_VOLC_ASR_APP_KEY
BV_VOLC_ASR_ACCESS_KEY
```

你不一定要同时配置全部变量。选哪条音频路线，就准备那条路线真正需要的内容。供应商字段、价格和音色权限可能变化，真实调用前要让 Agent 查当前官方资料。

## 新建一本书

只有书名和作者时运行下面这条命令。

```powershell
uv run bv new --title "遥远的救世主" --author "豆豆"
```

如果你有合法可读的本地文件，可以这样新建。

```powershell
uv run bv new .\book.txt --title "书名" --author "作者"
```

命令会返回一个 `book_id`。先让 Agent 看状态和下一步建议。

```powershell
uv run bv status --book-id <book_id>
uv run bv next <book_id>
```

这里先不要加 `--allow-external`。检查状态属于本地只读动作，不需要消耗云端额度。等 Agent 说清楚要调用哪家服务、发送什么输入、会生成什么文件，你再决定是否批准。

## 整个流程会在哪里停下来

第一个停点是文稿。

Agent 要交付一篇能代表整本书读者价值的口播稿，并说清楚事实来源和推断边界。你确认文稿以后，它才可以拿批准稿中的同一个片段做音色试听。

第二个停点是音色。

候选音色必须朗读同一段 15 到 25 秒的内容。这样你听到的差异主要来自声音本身。确认音色以后，Agent 才能生成完整旁白，再用最终 WAV 做 ASR 对齐。最终音频时长是字幕和画面的统一计时依据。

第三个停点是代表图。

Agent 会先给你看三张图，分别代表开头、中段和结尾。你要检查人物年龄、发型、衣服和关键物件是否一致，也要看画面有没有乱码、水印、假书封、畸形手部。通过以后才补齐总计四张背景图。

第四个停点是成片和独立封面。

自动 QC 能确认分辨率、编码、帧率、音轨、时长和文件哈希。它看不出情绪是否自然，也不能替你判断人物是否越画越不像。你需要完整看完视频，再明确说最终批准。

## 一段可以直接复制给 Agent 的任务书

把下面内容复制到 Agent 对话里。最后一行替换成你的书名和作者，或本地文件路径。

```text
你现在接手开源项目 https://github.com/kaiteJiang/book-video-workstation 。

先读取仓库根目录的 README.md、config.example.yaml、AGENTS.md，
再读取 docs/runbooks/handdrawn-codex-production.md。
先做只读预检，运行 uv run bv doctor、git status 和当前项目状态检查。
不要先安装大型模型，不要先调用云服务，不要先批量生成图片。

安全规则如下。
不要打印、复述、写入或提交 API Key、Token、Cookie、签名 URL。
不要把电子书正文、私人笔记、试听音频、供应商原始响应和成片提交到 Git。
发现疑似敏感信息时只报告文件路径和风险类型，不显示真实内容。

按以下门禁推进。
一，先理解整本书和证据边界，交付 30 到 45 秒中文口播稿，等我确认。
二，文稿确认后，用同一段原文制作音色试听，等我确认音色。
三，音色确认后生成正式旁白，用最终 WAV 做 ASR 和字幕时间轴。
四，画风固定使用第 11 种 retro-gouache-concept，中古动画水粉概念稿。
五，整条视频总计四张背景图。先生成开头、中段、结尾三张代表图，等我确认，再补第四张。
六，渲染 1080x1920、30fps 的竖屏视频，时长必须在 30 到 45 秒。
七，另做一张 1080x1440 的 3:4 独立封面，单独给我确认。
八，没有真实音频、字幕、图片、MP4、manifest、ffprobe 事实和 QC 报告时，不要声称完成。
九，不上传任何内容平台，除非我以后单独授权。

每次需要外部调用前，告诉我服务名称、准备发送的内容、预计产物、是否可能收费。
一次批准只覆盖当前说明的调用，不自动覆盖失败重试、换音色、换供应商或下一阶段。
如果本地已经存在批准记录和合格产物，从第一个未完成门禁继续，不要从头重做。

这次输入是 书名《在这里填写》，作者 在这里填写。
```

## 怎么判断 Agent 真的做完了

先看文件，再听说法。

一个合格交付至少要有最终旁白 WAV、字幕文件、四张背景图、竖屏 MP4、独立三比四封面、渲染清单和 QC 报告。Agent 还要给出 FFprobe 能确认的分辨率、帧率、音视频编码和时长事实。

如果它只说任务已提交、进程已结束、图片已生成，那都还不是成片完成。云端任务 ID 只能证明提交过，不能证明文件已下载。渲染进程退出也只说明命令结束，不能证明视频可播放。

最后检查 Git 状态。公开提交里不应出现 `.env`、`config.yaml`、`workspace/books/`、`workspace/voices/`、WAV、MP4、EPUB 和供应商私有回执。

## 常见卡点

`doctor` 找不到 FFmpeg，往往是配置路径不对，或 Agent 进程还保留着旧 PATH。让它同时检查绝对路径和普通命令解析结果。

只有书名和作者，Agent 却直接写整本书观点，说明证据边界还没建立。让它列出已确认事实、公开资料、私人笔记和自己的推断，不能混写。

声音听起来不自然，先换试听音色，不要直接重做整条视频。试听必须使用同一段文案，否则你很难判断差别来自音色还是文本。

四张图人物不一致，回到代表图门禁修人物锁和关键物件。不要一边生成剩余图片，一边继续改主角设定。

成片时长越界，先检查最终 WAV。这个项目把最终旁白当作全局时间轴，画面不能靠随意加速来掩盖口播太长。

## 这套方法为什么值得开源

Agent 很会把动作做完，也很容易把动作当成果。图书视频同时碰到版权、隐私、付费接口、声音审美、画面一致性和编码规范。只靠一段万能提示词，很难稳定复现。

开源仓库能把这些经验变成可检查的合同。后来的人可以替换声音模型、图片供应商或渲染器，也能保留文稿审批、同片段试听、代表图、最终 QC 这些关键门禁。

你可以从一条视频开始。先让 Agent 把环境检查跑通，再给它一本你真正了解的书。第一次慢一点没关系。等流程有了可信的批准记录和交付清单，第二本书才会真的更快。
